# 组织能力视图升级：去噪 + 组织建设

## 一、为什么现在看着「信息多但单薄」

当前逻辑把每个岗位画像里的每一条专业领域/知识/技能/领导力都拆成一项能力，只要这个岗位没人，全部落进「无人承载」。所以一个空缺岗位就能刷出 22 项红色条目——它们其实是**同一个原因**：这个岗位还没招到人。

## 二、优化方向

### 1. 按「根因」收敛，而不是按条目铺开
- 先判断根因：如果某项能力的全部来源岗位都没有在岗人员，它归入 **「岗位空缺导致」**。
- 这类能力不再逐条罗列，而是折叠成一张卡片：`岗位「XXX」尚未到岗 → 影响 22 项能力`，点击才展开明细。
- 真正需要关注的是另一类：**岗位有人，但这项能力没人扛得起来**（人在、能力不在），这才逐条列出。

### 2. 只保留有信号的条目
- 合并近义项（现有归一化基础上再合并包含关系，如「NPU 架构」与「NPU 架构设计」）。
- 按重要度排序：来源岗位的 criticality + 要求熟练度 + 被多少岗位共同要求，低信号的折叠进「更多」。
- 顶部结论改为三句话：多少能力靠招聘解决、多少靠现有人补齐、多少已经站稳。

### 3. 每项能力给一个「下一步」
每行给出可执行建议，而不只是状态：招聘 / 指定第二承载人 / 安排内部分享 / 外部培训。这也正好和下面的组织建设联动。

## 三、新增「组织建设」模块（同一页面第二块）

组织能力不只是岗位画像，还包括团队怎么被建设起来。新增一个活动记录层：

**记录内容（一条活动）**
- 类型：团建 / 技术分享 / 例会 / 培训 / 复盘 / 跨团队交流 / 招聘宣讲
- 标题、日期、组织者、参与人（关联人员表）、时长
- 关联方向、关联能力标签（可选）
- 成果/纪要链接、备注

**页面呈现**
- 顶部节奏条：近 90 天活动数、按类型分布、人均参与次数。
- 参与度：谁参与最多、谁连续 90 天没参加过任何活动（团队氛围风险信号）。
- **能力建设联动**：技术分享/培训如果关联了能力标签，就在能力清单里标出「近期有内部分享」——说明这项能力正在被主动建设，而不是只靠一个人硬扛。
- 建议区：对「只靠 1 人」的能力，自动建议「安排一次内部分享 + 指定第二承载人」。

## 四、技术实现

- 新表 `org_activities`（类型、标题、日期、组织者、时长、方向、能力标签、纪要链接、备注）+ `org_activity_participants`（活动 ↔ 人员）。RLS 沿用现有 authenticated 读写。
- `src/lib/capability.ts`：增加根因分类（`vacancy` vs `capability_gap`）、近义合并、重要度权重、建议生成。
- `src/lib/org-building.ts`：活动统计与参与度计算。
- `src/routes/capability.tsx`：重构为「能力体检」+「组织建设」两块，能力清单默认折叠空缺根因卡片。
- 新增活动录入抽屉组件，破坏性操作沿用 `ConfirmAction`。
