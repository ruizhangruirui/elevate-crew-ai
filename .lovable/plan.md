# 系统自带账号 + Owner / HR / 主管 权限

## 已完成
- 绩效与成长页的人才九宫格已删除（个人页上的"九宫格位置"标签也一并去掉）。

## 要做什么

**1. 账号完全由系统自己管理**
- 不再有"注册"入口，登录页只剩 邮箱 + 密码。
- 账号和密码（加密存储，不可反查）保存在你们自己的数据库里，内网部署后不依赖任何外部登录服务。
- 首个 Owner：第一次打开系统时，如果还没有任何账号，显示"创建 Owner 账号"表单；之后此入口永久关闭。

**2. Owner 在「系统设置 → 权限管理」里管理用户**
- 新增用户：姓名、邮箱、角色（Owner / HR / 主管）、负责范围（主管选 Lab/Team）、初始密码。
- 编辑用户：改姓名、角色、范围；停用 / 启用。
- 删除用户：二次确认，写入操作记录。
- 重置密码：Owner 可以给某人设一个新的临时密码（忘记密码时的兜底）。

**3. 用户自己改密码**
- 左下角个人菜单 → "修改密码"：输入旧密码 + 新密码（两次）。
- 初始密码登录后顶部提示"建议修改初始密码"。

**4. 三种角色看到什么**

```text
Owner   全部功能 + 用户管理
HR      全部人才数据可看可改，不能管理用户
主管    只看/改自己负责的 Lab/Team 下的人；可做绩效、技能评估；
        看不到系统设置里的权限管理和人员导入
```

## 技术细节
- 新表 `app_users`（email 唯一、password_hash 用 PBKDF2/Web Crypto、role、scope_node_ids、status、must_change_password）与 `app_sessions`（随机 token 的哈希、过期时间）。表只允许服务端访问（不授权给浏览器角色）。
- 登录/登出/改密码/用户增删改全部走服务端函数；会话用 httpOnly cookie。
- 现有页面目前从浏览器直接读写数据库并依赖原登录服务的身份；改造为：所有读写通过服务端函数，统一校验会话与角色，主管的数据按范围过滤。这是本次工作量最大的部分，会按页面逐一迁移。
- 原 `access_users` 表停用并标记为 DEPRECATED；审计日志的"操作人"改为当前登录用户姓名。
- 现有登录服务的账号不再使用；迁移后需要用"创建 Owner"重新建第一个账号。
