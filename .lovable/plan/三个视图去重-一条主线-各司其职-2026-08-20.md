# 三个视图去重：一条主线，各司其职

## 一、现在重复在哪

| 现有页面 | 内容 | 与谁重复 |
| --- | --- | --- |
| 组织能力视图 | 能力体检、组织范围筛选、组织建设、趋势 | 「组织范围筛选」= 组织树的另一种表达 |
| 组织 & 人员视图 | Lab→Team→人 树、节点统计（编制/覆盖率/单点风险）、AI 团队诊断、未归属指派 | 节点统计里的覆盖率/单点风险 = 能力视图的指标 |
| 人员视图 | 人员名单、筛选、数据待补全 | 名单 = 组织树展开后的成员列表；待补全属于组织健康度 |

根本问题：**同一批指标在三处各算一遍**，用户在哪看都是"看起来全，其实是同一件事"。

## 二、方案：按「问题层级」重新切分，从 3 个页面变 3 个不重叠的层

```text
组织视图（结构层） →  能力视图（能力层） →  人员视图（个体层）
  "我们是怎么搭的"      "能力有没有缺口"       "具体是谁"
```

### 1. 组织视图 = 唯一的导航入口
- 保留 Lab→Team→人 树，作为全站的「结构地图」。
- 节点行上只保留**结构类**指标：在岗/编制、平均职级、承担方向。
- 覆盖率、单点风险这类**能力类**指标从节点行移除，改成一个「查看该团队能力体检 →」链接，带 scope 参数跳到能力视图。
- 未归属指派、AI 团队诊断留在这里（都是结构问题）。

### 2. 能力视图 = 只讲能力，不再重复画组织
- 去掉页面内的「组织范围」下拉选择器，改为从 URL scope 参数接收（由组织视图/首页跳转带入），顶部只显示"当前范围：XX 团队 · 切换"。
- 保留：能力体检、组织建设、趋势。
- 「组织建设」里的活动/参与度也按当前 scope 过滤，跟能力清单同一范围。

### 3. 人员视图 = 名单与数据质量
- 定位为「表格视图」：可搜索、可筛选、可导出的全员平铺列表（组织视图是层级，人员视图是平铺，用途不同不算重复）。
- 「数据待补全」从这里挪到组织视图的顶部横条（因为它是组织级健康度信号），人员视图只在每行右侧标一个"资料不全"小标记。

### 4. 首页
- 首页顶部三块指标分别链到对应的层：编制缺口→组织视图，能力覆盖率→能力视图，资料完整度→组织视图。

## 三、改动清单（技术）

- `src/routes/org.tsx`：节点行去掉 coverageRate / soleCarriers，加「能力体检」跳转链接；顶部加数据完整度横条（复用 `completeness()`）。
- `src/routes/capability.tsx`：scope 改为 `useSearch()` 读 URL 参数（`validateSearch` 加 `scope?: string`），移除内嵌下拉；组织建设按 scope 过滤。
- `src/routes/people.tsx`：移除「数据待补全」大区块，改为行内标记 + 一句「详见组织视图」。
- `src/lib/org-tree.ts`：`nodeStats` 拆成 `structureStats`（结构）与现有能力字段，避免组织视图重复计算能力。
- `src/routes/index.tsx`：三个统计块加跳转。

## 四、可选的更激进方案（如果你想更少页面）
把「组织 & 人员视图」和「人员视图」合并成一个页面，用「层级 / 列表」两个视图切换按钮，导航从 4 项减到 3 项。上面的方案不做这一步，因为两种浏览方式的使用场景确实不同；但如果你觉得导航太长，可以一并做。
